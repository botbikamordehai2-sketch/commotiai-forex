# 02 — WordPress Studio: מהירות, CLI ו-Studio Code

## פרטי מקור
- כותרת: WordPress Studio Just Got Faster, the CLI is Now Dependency-Free, and Sonnet 5 is Supported
- תאריך: 13 ביולי 2026
- מחבר: Fredrik Rombach Ekelund
- זמן קריאה: 4 דקות
- מקור:
  https://wordpress.com/blog/2026/07/13/faster-wordpress-studio/
- סטטוס: נלמד ונסרק
- נושא ראשי: סביבת פיתוח WordPress מקומית

## מטרת השיעור
להבין שלושה שדרוגים ב-WordPress Studio:

1. סביבת עבודה מקומית מהירה יותר באמצעות Native PHP Runtime
2. Studio CLI שניתן להתקין ללא Node.js או npm
3. Studio Code עם Sonnet 5 כברירת מחדל

## מסקנה מרכזית
WordPress Studio הוא כלי Local Development חינמי וקוד פתוח.

הוא מאפשר:
- יצירה וניהול של אתרי WordPress מקומיים
- פיתוח Themes, Plugins ו-Blocks
- בדיקות לפני הפצה
- עבודה דרך ממשק גרפי או טרמינל
- שימוש בסוכן AI שמבין את הקשר האתר המקומי

אין צורך לפרסם אתר או לחבר Hosting כדי ללמוד ולעבוד מקומית.

## חלק א' — Native PHP Runtime

### מה השתנה
WordPress Studio עבר ל-Native PHP Runtime כברירת מחדל.

לפי WordPress:
- טעינת דפים מקומיים מהירה ב-30% עד 50%
- צריכת זיכרון נמוכה משליש מהמצב הקודם
- השיפור מורגש במיוחד באתרי ניסוי עם הרבה Plugins

### למה זה חשוב
Runtime הוא שכבת ההרצה של PHP באתר המקומי.

Native Runtime:
- מהיר יותר
- משתמש בפחות זיכרון
- מתאים לפיתוח רגיל
- מתאים לבניית אתר או Theme שאתה מכיר וסומך עליו

### גרסת מינימום
Native PHP Runtime זמין ב-WordPress Studio 1.12.0 ומעלה.

בדיקה:
Site Settings → Edit site → PHP runtime

## חלק ב' — Sandbox Runtime

### מהו Sandbox
Sandbox Runtime מיועד להרצת קוד שאינך סומך עליו לחלוטין.

הוא מבוסס על WordPress Playground.

מטרתו:
- למנוע מהקוד להפעיל תוכנות אחרות במחשב
- למנוע גישה של הקוד מחוץ לתיקיית האתר
- ליצור הפרדה טובה יותר בעת בדיקת Theme או Plugin חיצוני

### מתי לבחור Sandbox
השתמש ב-Sandbox אם אתה:

- בודק Plugin שהורדת ממקור לא מוכר
- בודק Theme חיצוני
- בוחן ZIP של לקוח או ספק
- מריץ קוד AI לפני שאתה מכיר אותו
- בודק Plugin שנוצר על ידי סוכן AI
- רוצה לבצע ניסוי לפני העברה לסביבת Local רגילה

### מתי לבחור Native
השתמש ב-Native אם:

- אתה עובד על פרויקט שלך
- הקוד כבר נבדק
- אתה צריך מהירות
- אתה מריץ אתר עם הרבה Plugins
- אתה מפתח ושולט בקבצים

### כלל בטיחות
Unknown code → Sandbox Runtime

Reviewed code → Native Runtime

אין להעביר קוד לא מוכר ישירות לאתר חי.

## חלק ג' — Studio CLI

### מהו CLI
CLI הוא ממשק פקודות דרך Terminal או PowerShell.

במקום ללחוץ בממשק, אפשר:
- ליצור ולנהל אתרים מקומיים
- להריץ WP-CLI
- להפעיל פקודות פיתוח
- לבצע Pull או Push
- לעבוד בצורה סקריפטבילית
- להתחבר לכלי אוטומציה ו-CI בעתיד

### שינוי מרכזי
אין צורך להתקין Node.js או npm כדי להתקין Studio CLI.

ב-Windows מופיעה פקודת התקנה אחת:

```powershell
irm [https://wordpress.studio/install.ps1](https://wordpress.studio/install.ps1) | iex
```

### אזהרת אבטחה חשובה
הפקודה מורידה סקריפט מהרשת ומריצה אותו מיידית.

לכן, לפני הרצה:

1. פתח את כתובת הסקריפט בדפדפן.
2. ודא שהדומיין הוא `wordpress.studio`.
3. קרא את הסקריפט או שמור עותק לבדיקה.
4. ודא שיש לך גיבוי או נקודת שחזור.
5. הרץ רק לאחר החלטה מפורשת.

גישה בטוחה יותר:

```powershell
Invoke-WebRequest `
  -Uri "https://wordpress.studio/install.ps1" `
  -OutFile "$env:USERPROFILE\Downloads\wordpress-studio-install.ps1"
```

לאחר ההורדה:
- פתח את הקובץ ב-VS Code או Notepad
- בדוק שהוא סקריפט התקנה תקין
- רק לאחר review, החלט אם להריץ אותו

### האם חייבים CLI?
לא.

לשלב הראשון, Studio Desktop מספיק בהחלט.

CLI רלוונטי כאשר רוצים:
- אוטומציה
- WP-CLI
- עבודה עם Git ו-PowerShell
- CI/CD
- סקריפטים חוזרים
- ניהול מספר אתרי ניסוי

## חלק ד' — Sonnet 5 בתוך Studio Code

### מה השתנה
ב-Studio 1.14.0 ומעלה, Studio Code משתמש ב-Claude Sonnet 5 כברירת מחדל לפי המאמר.

אפשר לבחור מודל אחר:
- מתוך תפריט המודלים באפליקציית Desktop
- באמצעות הפקודה `/model` בטרמינל

### מה הסוכן יודע לעשות
Studio Code מקבל גישה להקשר של סביבת WordPress המקומית.

הוא יכול:
- לקרוא Logs
- לזהות קבצים רלוונטיים
- לעקוב אחרי תקלה בין מספר קבצים
- להסביר סיבת תקלה
- להציע שינוי לבדיקה
- ליצור Plugin
- ליצור Block מותאם
- ליצור Custom Post Type
- לשנות Theme
- להריץ פקודות פיתוח

### מה הסוכן אינו מחליף
Studio Code אינו מחליף:

- אימות אנושי
- בדיקת אבטחה
- Code Review
- Git Commit
- בדיקת מובייל
- בדיקת ביצועים
- בדיקת SEO
- אישור פרסום
- אחריות על תוכן פיננסי

## תהליך עבודה בטוח עם Studio Code

1. צור אתר Local חדש או Clone בסביבת Studio
2. בחר Sandbox Runtime לקוד חדש, חיצוני או לא מאומת
3. תעד דרישה ב-Notion
4. בקש מהסוכן תוכנית בלבד, ללא שינוי קבצים
5. בקש רשימת קבצים שהסוכן מתכוון לשנות
6. אשר שינוי קטן אחד בלבד
7. בדוק את התוצאה ב-Live Preview
8. בדוק Desktop, Tablet ו-Mobile
9. בדוק Logs וטעינת העמוד
10. תעד Keep / Revise / Revert
11. בצע Git Commit לפני כל ניסוי משמעותי
12. עבור ל-Native Runtime רק לאחר שהקוד מוכר ונבדק
13. העבר ל-Staging רק לאחר אישור ידני
14. העבר ל-Production רק לאחר גיבוי ובדיקת Staging
